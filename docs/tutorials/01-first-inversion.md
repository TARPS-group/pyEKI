# 1. From approximate conditioning to EKI

Ensemble Kalman methods estimate unknown quantities from noisy data using
nothing but forward evaluations of a model. They maintain an ensemble — a
collection of candidate parameter vectors — push the parameters through the
forward model, fit a Gaussian distribution to the resulting pairs of
parameters and predictions, and condition that Gaussian on the data actually
observed. The conditioning is a closed-form calculation on the fitted
Gaussian, so the method needs no derivatives, no adjoint, and no access to the
model's internals. Originally developed for state estimation in geophysical
data assimilation, the same operation can be applied to static inverse
problems.

That single operation supports two quite different goals:

1. **Approximate sampling.** Applied repeatedly with the data introduced
   gradually, it produces an ensemble that approximates the Bayesian
   posterior distribution.
2. **Approximate optimization.** Applied repeatedly with no limit on how much
   the data is counted, it drives the ensemble onto the best-fitting
   parameters.

We refer to the use of ensemble Kalman methods for both tasks as *Ensemble
Kalman Inversion* (EKI), and pyEKI supports both applications using the same
core functionality.

This page introduces the application of ensemble Kalman methods to the
solution of inverse problems. We start with the sampling perspective,
demonstrating how ensemble Kalman updates approximate conditional
distributions — the Bayesian posterior being one such conditional. We will
see how this approximation can be quite poor when nonlinearity is present,
motivating the typical iterative EKI algorithm, in which the ensemble update
is repeated along a sequence of intermediate target distributions.

For a bare working example with no explanation attached, see
{doc}`../user-guide/quickstart` and the landing page's quick example. See
{doc}`03-sampling-or-optimizing` for an EKI tutorial for optimization.

## Setup

pyEKI assumes the observations were generated by a model with additive
Gaussian noise:

$$y = \mathcal{G}(u) + \varepsilon, \qquad
  \varepsilon \sim \mathcal{N}(0, \Sigma).$$

- $u \in \mathbb{R}^P$ are the **parameters** to be estimated.
- $\mathcal{G} : \mathbb{R}^P \to \mathbb{R}^N$ is the **forward model**,
  mapping parameters to the quantities that were observed.
- $y \in \mathbb{R}^N$ is the **observation**, a single vector.
- $\Sigma$ is the **observation error covariance**, supplied by the user. It
  is not estimated.

Prior information about $u$ is supplied as a Gaussian,
$u \sim \mathcal{N}(m_0, C_0)$, and the two together define the **misfit**

$$\Phi(u) = \tfrac{1}{2}
  \bigl\lVert \Sigma^{-1/2}\bigl(y - \mathcal{G}(u)\bigr) \bigr\rVert_2^2 ,$$

which measures the discrepancy between the forward model prediction and the
observed data, in units of observation error. The sampling and optimization
goals are formulated precisely as:

1. **Sampling.** Characterize the posterior

   $$\begin{aligned}
     \pi(u \mid y) &\;\propto\; \pi_0(u)\, e^{-\Phi(u)} \\
       &\;\propto\; \mathcal{N}\bigl(u \mid m_0,\, C_0\bigr)\,
          \mathcal{N}\bigl(y \mid \mathcal{G}(u),\, \Sigma\bigr) .
   \end{aligned}$$

2. **Optimization.** Minimize the misfit, regularized by the prior:

   $$u^{\star} = \operatorname*{arg\,min}_{u \in \mathbb{R}^P} J(u) ,
     \qquad J(u) = \Phi(u)
       + \tfrac{1}{2} \bigl\lVert C_0^{-1/2}(u - m_0) \bigr\rVert_2^2 .$$

   $J(u)$ is $-\log \pi(u \mid y)$ up to an additive constant, so $u^{\star}$
   is the posterior mode — the maximum *a posteriori* (MAP) estimate.

$\mathcal{G}$ is treated as a black box throughout. pyEKI calls it and does
nothing else with it: no gradients, no adjoint, no linearization, no
assumption that it is differentiable or even continuous. It may be a Python
function, a compiled simulator, a subprocess, or a job submitted to a
scheduler.

What a run returns is an ensemble rather than a point estimate. In the
sampling case its spread *is* the uncertainty estimate.

:::{note}
**The Gaussian assumptions are on the interface, not on the method.** pyEKI's
arguments express a Gaussian prior and additive Gaussian observation error,
but the methodology is not confined to that setting. A non-Gaussian prior can
often be handled by reparameterizing — a positive parameter as the exponential
of a Gaussian one, a bounded parameter through a logit — so that the prior is
(approximately) Gaussian in the new variable and the transformation becomes
part of the forward model. Multiplicative or otherwise non-additive error can sometimes be
brought into the assumed form by transforming the observations instead, for
example by taking logarithms.

The cost is that both transformations make the forward model more nonlinear,
which is precisely what the iterative algorithm below has to absorb.
:::

## A toy problem

We work with a small problem provided in `pyeki.toy`. The forward model is a
decaying exponential,

$$\mathcal{G}(u)_i = a\, e^{-\lambda t_i}, \qquad i = 1, \dots, N ,$$

evaluated at $N = 12$ times $t_i$ evenly spaced over $(0, 3]$. There are two
parameters — an amplitude $a$ and a decay rate $\lambda$ — so the parameter
vector is

$$u = [a, \lambda]^{\top}, \qquad P = 2 .$$

We have noisy observations of the model output at those twelve times, and the
task is to recover the two parameters that produced them. The observations
here are synthetic, generated from $u = [2, 1.5]^{\top}$ with independent
noise of standard deviation 0.02, so there is a known answer to check
against; namely, `problem.u_true`.

```python
import pyeki  # enables float64; import this before creating any array
import jax
import jax.numpy as jnp
from pyeki import toy

problem = toy.exponential_decay()

problem.u_dim     # 2  -- P, the number of parameters
problem.v_dim     # 12 -- N, the number of observations
problem.u_true    # [2.  1.5]
problem.y[:4]     # [1.3705  0.929   0.6856  0.45  ]
```

:::{important}
Import `pyeki` before creating any array. It switches JAX to 64-bit floating
point. Arrays created before that import stay 32-bit and are **not** promoted
later, and a 32-bit forward model costs accuracy in the answer.
:::

The problem also carries the prior and the observation error covariance,
which for this problem are

$$m_0 = [1, 1]^{\top}, \qquad C_0 = I_2, \qquad
  \Sigma = 0.02^2\, I_{12} .$$

In pyEKI a covariance is represented as a **linear operator**: an object
defined by how it acts on vectors rather than by a stored matrix. See
{doc}`../user-guide/operators` for the catalogue and
{doc}`06-covariances-as-operators` for details. For now we use `PSDDiagonal`,
which represents a diagonal covariance matrix.

```python
from pyeki.gauss import Gaussian
from pyeki.linalg import PSDDiagonal

prior = Gaussian(mean=jnp.array([1.0, 1.0]),
                 cov=PSDDiagonal(jnp.array([1.0, 1.0])))
noise_cov = PSDDiagonal(jnp.full(12, 0.02 ** 2))
```

The toy problem already comes pre-built with these quantities, accessed at
`problem.prior` and `problem.noise_cov`.

### The forward model is called once with the whole ensemble

:::{important}
**A forward model takes the entire ensemble and returns the entire set of
predictions.** For an ensemble of $J$ members it receives one array of shape
`(J, P)` and returns one array of shape `(J, N)`:

$$\texttt{forward} : (J, P) \longmapsto (J, N).$$

Row $j$ of the return must depend only on row $j$ of the argument.

pyEKI does not assume responsibility for batching a forward model so that it
accepts ensembles as input. You may batch your model in whatever way you deem
computationally efficient — natively vectorized, a simple loop, distributed
over a computing cluster. pyEKI calls the batched forward model on the whole
ensemble one time per EKI iteration.
:::

For example, the exponential decay forward model could be written as follows:

```python
times = problem.times          # (12,) -- the observation times t_i

def forward(ensemble):         # (J, 2) in
    amplitude = ensemble[:, 0:1]                 # (J, 1)
    rate = ensemble[:, 1:2]                      # (J, 1)
    return amplitude * jnp.exp(-rate * times)    # (J, 12) out
```

The slices are written `0:1` rather than `0` so that they keep their second
axis and broadcast against `times`. This computes the same values as
`problem.forward`, exactly.

A model already written for one parameter vector should be wrapped rather than
rewritten. In JAX that is one line:

```python
def one_member(member):        # (2,) in
    return member[0] * jnp.exp(-member[1] * times)   # (12,) out

forward = jax.vmap(one_member)                       # (J, 2) -> (J, 12)
```

`jax.vmap` needs a model written in JAX. For anything else — a subprocess, a
compiled binary, a scheduler submission — the wrapper could be a loop or a
parallel map over the rows. See
{doc}`../user-guide/writing-a-forward-model` for more details.

### The prior ensemble

Every EKI run starts with an ensemble drawn from the prior distribution.
Below, we initialize this ensemble and evaluate the forward model at each
ensemble member. In Bayesian terminology, this yields samples from the *prior
predictive distribution*: model predictions generated from parameter vectors
sampled from the prior.

```python
from pyeki.eki import EKIState

state = EKIState.from_prior(jax.random.key(0), problem.prior, n_members=64)
state.ensemble.shape                     # (64, 2)

predictions = problem.forward(state.ensemble)
predictions.shape                        # (64, 12)
```

`jax.random.key` makes the typed keys JAX uses for random numbers; the same
key gives the same ensemble, so every number on this page is reproducible.
Those two shapes — `(64, 2)` in, `(64, 12)` out — are the convention above,
with $J = 64$.

The next section demonstrates that by conditioning on the observed data we can
narrow this spread.

## One-step approximate conditioning

We now consider how to transform the prior ensemble into an approximate
posterior ensemble. The mathematical details are beyond the scope of this
introduction — see {doc}`../user-guide/conditioning`, and
{doc}`../gaussian-contract` for the precise statements — but we describe the
process from a high level.

Pushing the prior parameter samples through the forward map yields samples
from the joint distribution over $(u, \mathcal{G}(u))$. This joint
distribution encodes the probabilistic coupling between the parameters and the
associated outputs of the forward model. Samples from the parameter–data joint
$(u, y) = \bigl(u, \mathcal{G}(u) + \varepsilon\bigr)$ can be obtained by
perturbing the outputs with sampled noise. The ensemble Kalman update is based
on a Gaussian approximation of this joint distribution, obtained by moment
matching to the sample mean and covariance of the joint samples. Since
Gaussians can be conditioned in closed form, we can use the closed-form
formula to transport the prior parameter samples into samples from the
distribution resulting from conditioning on the observed data $y$.

This description is a bit loose, but it touches on the key point that the
quality of the approximation will depend on how well $(u, y)$ can be
approximated by a Gaussian. The quality of the sample-based mean and
covariance estimates is another source of error to keep in mind, which depends
heavily on the size of the ensemble. The plots below summarize the result of
applying the one-step update.

```python
from pyeki.eki import FixedSchedule, PathwiseUpdate, run

one_step = run(state, problem.forward, problem.y, problem.noise_cov,
               schedule=FixedSchedule.constant(1.0, n_steps=1),
               update=PathwiseUpdate())

one_step.mean                            # [2.0227  1.666 ]
one_step.ensemble.std(axis=0, ddof=1)    # [0.0835  0.7719]
```

`PathwiseUpdate` is one of two ensemble update methods implemented in pyEKI,
representing the standard "perturbed observation" ensemble Kalman update. The
alternative transforms the ensemble deterministically instead; see
{doc}`05-transform-or-pathwise` for details.

```{figure} ../_generated/figures/01-one-step.png
:alt: Left, the true posterior's contours over amplitude and decay rate with the 64 members produced by one conditioning step. An arrow labelled G leads to the right panel, which shows those members' predicted decay curves with the observations overlaid.
:width: 100%

The analogs of the above plots, but now showing posterior rather than prior
quantities. Left: the ensemble members resulting from a single EKI step. The

```

The true posterior's contours are drawn here because this problem has only two
parameters, so its density can be evaluated directly on a grid. That is a
luxury of a small problem, not something available in general.

Observe that the EKI update collapses the ensemble around the area of high
posterior mass, but fails to accurately represent the shape of the posterior.
Thus, in this case, some promising parameter values were discovered but the
ensemble uncertainty is poorly calibrated. This suggests that the nonlinearity
of the exponential decay model rendered the joint Gaussian approximation
inappropriate here. Nonetheless, the predictions made from the updated
ensemble (right plot) do collapse around the observed data.

We can manually implement the moment-matching Gaussian approximation described
above to sanity check these results. The code below fits the joint Gaussian
approximation via moment matching, then conditions that Gaussian on the
observed data. The result is a Gaussian approximation to the posterior, with
mean and covariance that should approximately match the sample mean and
covariance of the ensemble above (they would match exactly if we had instead
used `TransformUpdate`). Note also that the higher moments are not at all
guaranteed to even approximately match; the EKI update rests on matching the
first two moments.

```python
from pyeki.gauss import GaussianJoint

joint = GaussianJoint.from_samples(u_samples=state.ensemble,
                                   v_samples=problem.forward(state.ensemble))
conditioned = joint.condition(problem.y, problem.noise_cov)

conditioned.mean                     # [2.0129  1.6505]
conditioned.cov.diag() ** 0.5        # [0.0781  0.7632]
```

## Improving the approximation with multiple steps

While a single EKI step nudged the ensemble members toward the region of high
posterior mass, its posterior approximation is quite poor. The discrepancy
does not go away with a larger ensemble: it is the Gaussian approximation that
is at fault, not the finite sample size.

The true joint distribution over $(u, y)$ is quite curved, and a Gaussian is
unable to describe this curvature. The problem is exacerbated by the small
amount of observation noise; noisier observations would serve to obscure the
curvature and thus make the joint more amenable to Gaussian approximation.
Concretely, since $(u, y) = \bigl(u, \mathcal{G}(u) + \varepsilon\bigr)$, the
more the Gaussian noise $\varepsilon$ dominates $\mathcal{G}(u)$, the more
this distribution will look Gaussian.

This suggests the following idea: artificially inflate the noise level, and
slowly reduce it back to its nominal level in a sequence of steps. The
concentrating effect of conditioning on the data is thus introduced gradually,
the idea being that a sequence of easier problems will be easier to solve than
one hard problem. Each step's target is then only slightly more concentrated
than the last, so the ensemble only has to move a little, and the Gaussian
approximation only has to hold over that short distance.

Precisely, consider a bridge of distributions interpolating between the prior
and the posterior. Writing
$L(u) = \mathcal{N}\bigl(y \mid \mathcal{G}(u),\, \Sigma\bigr)$ for the
likelihood,

$$\pi_\beta(u) \;\propto\; \pi_0(u)\, L(u)^{\beta} \;\propto\;
  \pi_0(u)\, \mathcal{N}\bigl(y \mid \mathcal{G}(u),\, \Sigma/\beta\bigr) ,
  \qquad \beta \in [0, 1] ,$$

where $L(u)^{\beta} \propto e^{-\beta \Phi(u)}$ with $\Phi$ the misfit defined
in the setup above. Setting $\beta = 0$ and $\beta = 1$ recovers the prior and
posterior, respectively. Values in between yield intermediate posteriors with
inflated noise. The above proportionality shows that, under our Gaussian
assumptions, tempering the likelihood (raising it to a power) is equivalent to
scaling the observation noise.

Since these distributions assume the recursive form

$$\pi_{\beta_{t+1}}(u) \;\propto\; \pi_{\beta_t}(u)\, L(u)^{\Delta\beta_t}
  \;\propto\; \pi_{\beta_t}(u)\,
  \mathcal{N}\bigl(y \mid \mathcal{G}(u),\, \Sigma/\Delta\beta_t\bigr) ,$$

for a sequence $0 = \beta_0 < \beta_1 < \cdots < \beta_T = 1$ with increments
$\Delta\beta_t = \beta_{t+1} - \beta_t$, tracking them implies solving a
sequence of Bayesian inverse problems: the intermediate posterior at one step
becomes the prior for the next step. The ensemble Kalman update is applied at
each step to perform the approximate conditioning. Because every step
conditions on noisier data than the original problem does, the distance from
each step's prior to its posterior is shorter, and correspondingly easier to
approximate.

We will sometimes refer to the values of $\beta$ as *tempering levels*, with
the sequence of them forming a *ladder*. The sequence of step sizes can have a
large impact on algorithm performance; see {doc}`04-tempering-schedules` for
details.


We see that some steps change the shape of the distribution more than others.
In this example, the first step appears the most concerning for an EKI

mainly by concentration, with little change in shape.

## A complete EKI run

We now execute a full multi-step EKI run. Rather than manually choosing the
tempering values (like above), we instead utilize a method that automatically
adapts the step size as the algorithm runs.

```python
from pyeki.eki import AdaptiveESSSchedule

result = run(state, problem.forward, problem.y, problem.noise_cov,
             schedule=AdaptiveESSSchedule(), update=PathwiseUpdate())

result.status            # 'schedule_exhausted' -- the ladder reached beta = 1
result.n_evaluations     # 8 -- batched forward model calls
result.beta              # 1.0
```

This run required eight calls of the batched forward model, each on 64
ensemble members, implying 512 parameter evaluations in total. See
{doc}`04-tempering-schedules` for details on the adaptive tempering levels.

```{figure} ../_generated/figures/01-bridge-tracked.png
:width: 100%

The contours of the (exact) bridging distributions, at the levels chosen by
the adaptive method. The EKI ensemble approximating each distribution is
overlaid. Panels are scaled independently, and each dashed rectangle marks the
```

The ensemble tracks the distributions fairly well, and the final posterior
approximation is far superior to the one-step result from before. EKI
struggles the most during the first step. As we predicted above, the curvature
present at the second distribution presents a challenge.

Once the algorithm has run, we can investigate the output.

```python
result.ensemble.shape                 # (64, 2)
result.mean                           # [1.978   1.4771]
result.ensemble.std(axis=0, ddof=1)   # [0.0414  0.0318]
```

Since we know the true posterior in this case, we can compute how well the EKI
ensemble approximates its mean and covariance. The code below computes the
mean and covariance of the true posterior on a dense grid, for comparison with
the EKI estimates.

```python
import jax.numpy as jnp
from pyeki.eki import misfits

amp = jnp.linspace(1.70, 2.25, 400)
rate = jnp.linspace(1.25, 1.70, 400)
A, R = jnp.meshgrid(amp, rate, indexing="ij")
grid = jnp.stack([A.ravel(), R.ravel()], axis=-1)      # (160000, 2)

log_density = (problem.prior.log_density(grid)
               - misfits(problem.y, problem.forward(grid), problem.noise_cov))
weights = jnp.exp(log_density - log_density.max())
weights = weights / weights.sum()

exact_mean = (weights[:, None] * grid).sum(axis=0)
centred = grid - exact_mean
exact_cov = (weights[:, None] * centred).T @ centred

exact_mean                            # [1.9769  1.4719]
jnp.sqrt(jnp.diag(exact_cov))         # [0.0366  0.0317]
```

| | mean | standard deviation | correlation |
| --- | --- | --- | --- |
| EKI ensemble | `[1.9780, 1.4771]` | `[0.0414, 0.0318]` | 0.864 |
| true posterior | `[1.9769, 1.4719]` | `[0.0366, 0.0317]` | 0.822 |

The mean agrees to within 0.006 in both parameters, and the decay rate's
spread to within a fraction of a percent; the amplitude's spread comes out
about 13% too wide.

One thing to keep in mind is that the ensemble samples are not independent:
the EKI update couples them through the sample mean and covariance estimates.
The degree of this coupling depends on the ensemble size.
